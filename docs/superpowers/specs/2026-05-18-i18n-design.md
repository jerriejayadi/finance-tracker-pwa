# Internationalization (i18n) Design Spec

**Date:** 2026-05-18
**Languages:** English (default), Bahasa Indonesia
**Library:** next-intl (cookie-based, no URL prefixes)

---

## 1. Infrastructure

### Locale Config
- Default locale: `en`, supported: `['en', 'id']`
- `src/i18n/config.ts` — shared constants (locales list, default locale, cookie name `NEXT_LOCALE`)
- `src/i18n/request.ts` — next-intl request config, reads locale from cookie

### Message Files
- `src/messages/en.json`, `src/messages/id.json`
- Namespaced by feature:
  - `common` — shared strings: "Save", "Cancel", "Today", "Yesterday", etc.
  - `auth` — login, register, onboarding
  - `dashboard` — home page
  - `history` — transaction history
  - `budget` — budget page
  - `profile` — profile/settings
  - `transaction` — add/edit transaction drawer

### Key Naming
- camelCase, descriptive: `"totalBalance"`, `"recentActivity"`, `"seeAll"`, `"noTransactions"`

### Middleware Update
- Chain `createMiddleware` from next-intl with existing Supabase auth middleware
- Reads `NEXT_LOCALE` cookie → sets locale header for server components
- No URL rewrites — clean URLs preserved (`/dashboard`, `/budget`, etc.)

### Root Layout
- `lang` attribute reads from next-intl instead of hardcoded `"en"`
- Wrap children with `NextIntlClientProvider` for client component access

---

## 2. Component Integration

### Server Components
- `getTranslations('namespace')` from `next-intl/server`
- Example: `const t = await getTranslations('dashboard')` → `t('totalBalance')`

### Client Components
- `useTranslations('namespace')` hook
- Example: `const t = useTranslations('profile')` → `t('signOut')`

### Dynamic Values
- ICU message format: `t('saved', { amount: 5000 })` → "Saved Rp5,000"
- Plurals: `t('transactions', { count: 3 })` → "3 transactions" / "3 transaksi"

### date-fns Locale
- Create `src/lib/date-locale.ts` — maps app locale string to date-fns locale object (`en` → `enUS`, `id` → `id`)
- Pass locale to all `format()` calls

---

## 3. Language Picker & Persistence

### Source of Truth
- **Rendering:** `NEXT_LOCALE` cookie (read by middleware on each request)
- **Storage:** `language` column in Supabase `profiles` table

### Registration (Profile Setup)
- Add language select field to profile setup form (`/register?step=profile`)
- Dropdown or toggle: "English" / "Bahasa Indonesia"
- On submit: save to Supabase profile + set `NEXT_LOCALE` cookie

### Profile Settings
- Add "Language" row in settings list (near "Currency")
- Tap opens drawer or inline toggle to switch EN ↔ ID
- On change: update Supabase profile + update cookie + reload page

### Authentication Flow
- On login: read user's `language` from profile → set `NEXT_LOCALE` cookie
- Unauthenticated users: default to `en`, or detect `id` from browser `Accept-Language`

### Supabase Schema
- Add `language` column to `profiles` table
  - Type: `text`
  - Default: `'en'`
  - Check constraint: `language IN ('en', 'id')`

---

## 4. String Extraction Strategy

### Process
1. Extract all ~200-400 inline strings into `en.json` (namespaced)
2. Create `id.json` as copy, translate values to Bahasa Indonesia
3. Replace inline strings with `t('key')` calls, component by component

### What NOT to Translate
- User-generated content (transaction notes, category names)
- Currency codes/symbols (handled by `Intl.NumberFormat`)
- Brand name "FinTrack"
